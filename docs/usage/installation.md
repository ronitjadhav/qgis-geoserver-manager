# Installation

## Released version

There is no release yet, so the plugin is not on the official QGIS plugins
repository and the
[releases page](https://github.com/ronitjadhav/qgis-geoserver-manager/releases) is
empty. Until then, install the
[development version](#latest-development-version) below.

Once released, it will be at
<https://plugins.qgis.org/plugins/geoserver_manager/> and install directly from
the plugins manager. A release zip will also be on the releases page, for
*Plugins → Manage and Install Plugins → Install from ZIP*.

### Using this plugin with QGIS Deployment Toolbelt (QDT)

If you want to use this plugin with [QGIS Deployment Toolbelt (QDT)](https://qgis-deployment.github.io/qgis-deployment-toolbelt-cli/), you can add the following snippet to your `profile.json` file, under the `plugins` attribute:

```{eval-rst}

  :language: json
```

Remember to replace the `version` attribute with the version you want to install.

## Beta versions

The plugin is flagged as experimental, so enable experimental extensions in the
QGIS plugins manager settings panel to see it.

## Latest development version

If you define yourself as early adopter or a tester and can't wait for the release, the plugin is automatically packaged for each commit to main, so you can use this address as repository URL in your QGIS extensions manager settings:

```text
https://ronitjadhav.github.io/qgis-geoserver-manager/plugins.xml
```

Be careful, this version can be unstable.

## Network settings

### Behind a proxy

The plugin goes through the HTTP proxy set in QGIS's
*Settings → Options → Network*, except for the URLs excluded there. It passes
that proxy on to Python's `requests`, which the plugin and its REST library
use, as QGIS's `HTTP_PROXY` and `HTTPS_PROXY` environment variables, each
time the dialog connects. *Test connection* hands the proxy of the URL as
typed to its own requests instead, and leaves the variables alone. So:

- A variable you set yourself before starting QGIS wins over QGIS's proxy.
- With the *DefaultProxy* type (the system's proxy), `requests` reads the
  system's settings itself. It cannot read a proxy auto-configuration (PAC)
  script: set `HTTPS_PROXY` then.
- A SOCKS proxy is not passed on.
- Other Python plugins, and the programs QGIS starts, see the variables too,
  with the proxy's user name and password when it has them, until the plugin
  is disabled or uninstalled.
- After changing the proxy, press *Refresh* in the dialog.

### A private certificate authority

The plugin does not read QGIS's certificate store. Its requests check the
server's certificate against the certificate authorities (CAs) that Python's
`requests` knows. For a GeoServer whose certificate comes from a private CA:

1. Make a PEM file that holds that CA and the usual public ones, for instance
   a copy of `certifi`'s bundle with the CA appended. In QGIS's Python
   console, `import certifi; certifi.where()` gives that bundle's path.
2. Set the `REQUESTS_CA_BUNDLE` environment variable to that file. QGIS's
   *Settings → Options → System → Environment* sets it for QGIS alone. Then
   restart QGIS.
3. For the layers the plugin adds to QGIS, import the CA into QGIS's
   certificate manager too (*Settings → Options → Authentication*).

Untick *Verify the server's TLS certificate* in the plugin's settings only as
a last resort: it turns the check off for the plugin's requests, and does
nothing for the layers.
